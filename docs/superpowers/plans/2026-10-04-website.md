# Question Bank Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the full static website (bank, filters, set builder, practice, mock exam, copy, PDF/Word export, board and admission browsing) on Cloudflare Pages, running on about 20 sample SSC Physics questions plus the content validator that every later content PR must pass.

**Architecture:** Bilingual YAML content in `content/` is validated against JSON Schema and extra rules, then compiled by `scripts/build-data.ts` into per-chapter JSON (with KaTeX pre-rendered to HTML), per-subject manifests and MiniSearch indexes under `public/data/`. Astro generates static pages from the syllabus files. Preact islands load chapter JSON on demand and do all filtering, selection, practice, timing and export in the browser.

**Tech Stack:** Node 22, TypeScript, Astro 5 + @astrojs/preact, KaTeX, js-yaml, Ajv, MiniSearch, docx, Vitest, Playwright, GitHub Actions, Cloudflare Pages.

**Spec:** `docs/superpowers/specs/2026-10-04-question-bank-design.md`

**Out of this plan:** the content pipeline (Opus blueprint, Sonnet draft/check, Opus supervision), board and admission collection, and the full pilot chapters. These come in a second plan, written after this one ships. This plan builds only the validator those PRs will rely on.

## Global Constraints

- Science group only; levels `ssc` and `hsc`.
- Every text field is `{bn, en}`; both are required and non-empty.
- Math is LaTeX between `$…$`.
- Difficulty is one of `easy` / `medium` / `hard`.
- MCQ types: `gyanmulok`, `onudhabon`, `bohupodi`, `ovinno`.
- CQ parts: `ka` (1 mark), `kha` (2), `ga` (3), `gha` (4).
- Status: `draft` → `checked` → `reviewed`. Builds show only `reviewed` unless `SHOW_DRAFTS=1`, in which case `checked` questions are also shown with a "Draft" label.
- Mock exam: 25 MCQs in 25 min (1500 s), then CQs as 5 of 8 in 2 h 35 min (9300 s).
- Set builder never pads with non-matching questions.
- No login. Per-student data lives in `localStorage` only, and every access must survive storage throwing.
- PDF goes through a print stylesheet plus `window.print()`, never an in-browser PDF library. Word goes through the `docx` package in the browser.
- Fonts: Noto Sans Bengali (Bangla) plus Inter (Latin), from Google Fonts.
- Hosting: Cloudflare Pages free tier. Build command `npm run build`, output `dist/`.

## Review Focus

1. **Set builder asked for more than the pool holds.** Return everything that matches, report the shortfall, and never pad. Test in Task 6.
2. **অভিন্ন তথ্যভিত্তিক MCQ sets split apart.** Selection, filtering and display must keep questions with the same `stimulus_id` together and show the stimulus once. Tests in Tasks 5 and 6.
3. **Malformed math or mixed Bangla+LaTeX text.** An unbalanced `$` must fail validation, and the KaTeX renderer must not crash the build on bad LaTeX (render the raw text and log a warning). Tests in Tasks 3 and 4.
4. **Storage blocked (private mode, Safari ITP).** Bookmarks, scores and the mock timer must degrade silently. Test in Task 9.
5. **Mock exam reloaded or tab backgrounded.** Remaining time is computed from a stored start timestamp, not from counting interval ticks. Test in Task 10.

export type Bi = { bn: string; en: string };

export type Level = 'ssc' | 'hsc';

export type Source =

Rules, each its own exported function:

| rule | severity |
|---|---|
| `schema` | error |
| `bilingual-nonempty` (every Bi has non-blank bn and en) | error |
| `math-delimiters` (even, non-escaped `$` count per string) | error |
| `unique-id` (across all content) | error |
| `topic-exists` (topics ⊆ syllabus chapter topics, chapter slug exists) | error |
| `distinct-options` (normalised option text unique per language) | error |
| `stimulus-ref` (every `stimulus_id` resolves within the file; every stimulus used ≥ 2 times) | error |
| `paper-ref` (paper ids resolve to existing questions whose source matches the paper) | error |
| `figure-exists` | error |
| `computable` (evaluate `expr` with a whitelist evaluator; must be within `tolerance ?? 1e-6` of `expected`, and `expected` must appear in the correct option's English text) | error |
| `near-duplicate` (normalised English stem, Jaccard similarity of word trigrams ≥ 0.85 within a subject) | warning |

### Task 6: Seeded set builder

**Files:**
- Create: `src/lib/rng.ts`, `src/lib/set-builder.ts`, `tests/set-builder.test.ts`

**Interfaces:**
- Produces:
```ts
export function mulberry32(seed: number): () => number
export function shuffle<T>(arr: readonly T[], rand: () => number): T[]   // Fisher–Yates, no mutation
export interface SetRequest { level: Level; subject: string; chapters: string[]; topics?: string[];
  difficulty: Difficulty[]; mcqTypes?: McqType[]; mcqCount: number; cqCount: number }
export interface QuestionSet { request: SetRequest; seed: number; mcqs: Mcq<RichBi>[]; cqs: Cq<RichBi>[];
  available: { mcq: number; cq: number }; shortfall: boolean }
export function buildSet(pool: CompiledQuestion[], req: SetRequest, seed: number): QuestionSet
export function encodeSet(req: SetRequest, seed: number): string
export function decodeSet(search: string): { req: SetRequest; seed: number } | null
```
- How selection works:
  - Filter the pool by the request using `filterQuestions` (Task 5).
  - Treat each ovinno set as one unit worth its size. Shuffle the units with `mulberry32(seed)`, then take units in order. Skip any unit that would push the total past `mcqCount`.
  - CQs are shuffled and sliced.
  - `shortfall` is true when fewer than requested were returned.
  - The output order is the shuffled order, with each ovinno set's members kept adjacent.

- [ ] **Step 1:** Write the tests.
  - The same seed gives identical ids; a different seed gives a different order (seed fixed in the test).
  - Asking for 50 MCQs from a pool of 12 returns 12 with `shortfall: true` and `available.mcq === 12`, and every returned question matches the request.
  - With `mcqCount: 1` and a pool containing only an ovinno pair plus one single, the result is the single, never half a pair.
  - `decodeSet(encodeSet(r, s))` round-trips.
  - `decodeSet('?junk')` returns `null`.
